The review points out that the spec's failure cases and/or acceptance criteria are vague or
generic (e.g. "handle errors gracefully", "all edge cases covered", "work correctly", "notified as needed",
"security is ensured") and therefore don't specify checkable behaviour. Passing requires calling out the
vagueness of these spec lines specifically, not only reviewing the code.
